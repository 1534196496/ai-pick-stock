# 基金分析

使用官方历史净值和带日期的公开信息分析基金。不得把盘中估值当作官方净值，也不得用股票技术指标生套基金。

## 工作流

1. 从用户输入提取六位基金代码；无法确认时先说明。
2. 运行取数脚本：

   ```bash
   python3 /app/agent_skills/fund-analysis/scripts/fund_data_fetcher.py --fund "基金代码"
   ```

3. 只使用脚本 JSON 中的数值分析官方净值趋势、阶段收益、波动和回撤。
4. 输出简洁结论，并保留数据日期、来源和限制。
5. 默认不搜索新闻或公告，避免非核心查询拖慢净值分析。只有用户明确询问消息面时才搜索最多 3 条，优先基金公司公告、基金定期报告和监管信息；找不到就明确写“近期消息未核实”，不得编造。

## 判断规则

- 最新官方净值日期落后于自然日时，按原日期展示。QDII 净值通常滞后，不得强行改成当天。
- 短期趋势参考 MA5 与 MA20，中期趋势参考 MA20 与 MA60；历史不足时省略对应判断。
- 风险必须结合最大回撤、当前回撤、年化波动和阶段收益，不以单日涨跌下结论。
- 只给条件化操作建议，例如“回撤收窄且重新站上 MA20 后再观察”；不承诺收益。
- 数据为空、结构异常或网络失败时停止分析并说明原因，不生成虚假数值。

## 输出格式

按以下顺序输出：

1. `结论`：偏强、震荡、偏弱或数据不足，并用一句话解释。
2. `核心数据`：最新官方净值与日期、近 5/20/60/250 个净值日收益、最大回撤、当前回撤、年化波动。
3. `趋势与风险`：最多各 3 条，区分事实和推断。
4. `操作条件`：持有者和观察者各给一条可执行条件。
5. `数据说明`：数据源、抓取时间、QDII 或数据滞后说明、免责声明。

多轮追问必须沿用本轮已获取的数据；只有用户要求刷新或数据明显过期时才重新取数。

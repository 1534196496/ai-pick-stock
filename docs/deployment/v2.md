# V2 部署、备份与恢复

## 安全边界

- V2 Web 和 API 只绑定宿主机回环地址，PostgreSQL 不映射宿主机端口。
- `.env.v2`、数据库备份和 SMTP 凭据只保存在服务器，不进入 Git。
- 所有部署动作使用 `compose.v2.yaml`，不修改旧 Streamlit 的 `compose.yaml`、SQLite 或数据卷。
- 恢复脚本只接受 `aipickstock_restore_` 开头的全新临时数据库名，拒绝覆盖现有数据库。

## 启动与检查

```bash
V2_ENV_FILE=.env.v2 docker compose -f compose.v2.yaml config --quiet
V2_ENV_FILE=.env.v2 docker compose -f compose.v2.yaml up -d --build
V2_ENV_FILE=.env.v2 docker compose -f compose.v2.yaml ps
curl --fail http://127.0.0.1:18000/api/v1/health/live
curl --fail http://127.0.0.1:18000/api/v1/health/ready
```

生产环境必须设置 `AIPICKSTOCK_ENVIRONMENT=production`、正式公开 URL、强随机 PostgreSQL 密码和容器可达的 SMTP。行情联网需显式设置 `AIPICKSTOCK_MARKET_DATA_LIVE_ENABLED=true`。

服务器并行验证使用 18080，不触碰域名上游：

```bash
V2_ENV_FILE=.env.v2 docker compose \
  -f compose.v2.yaml -f compose.v2.production.yaml up -d --build
```

获得域名切换授权且旧服务已在 8501 验证健康后，V2 才改绑 8502：

```bash
V2_WEB_PORT=8502 V2_ENV_FILE=.env.v2 docker compose \
  -f compose.v2.yaml -f compose.v2.production.yaml up -d --force-recreate web
```

`V2_ENV_FILE` 选择容器环境文件；`V2_WEB_PORT` 是 Compose 插值变量，必须在命令环境中显式传入，二者不能混为一项。

## Caddy 切换与回滚草案

- V2 草案：`deploy/caddy/Caddyfile.v2.draft`，上游为 `127.0.0.1:18080`。
- 回滚草案：`deploy/caddy/Caddyfile.rollback.draft`，上游为 `127.0.0.1:8502`。
- 两份文件都不包含 Basic Auth；是否移除现有认证必须随域名切换单独获批。
- 应先把草案复制到服务器临时路径运行 `caddy validate --config <临时文件>`，不能直接覆盖生效配置。
- 切换前保存生效配置副本；加载新配置后检查 HTTPS、登录、API、持有和自选。
- 任一核心检查失败时立即加载回滚草案；V2 容器和 PostgreSQL 卷保留排查，不执行 `down -v`。

## 创建备份

```bash
V2_ENV_FILE=.env.v2 ./deploy/scripts/backup-postgres.sh
```

脚本使用 PostgreSQL custom format 创建一致性备份，先执行 `pg_restore --list` 校验，再原子改名，并生成 SHA-256 文件。默认目录为忽略提交的 `backups/postgres/`，目录权限为 `0700`，文件权限为 `0600`。

## 恢复到临时数据库

```bash
V2_ENV_FILE=.env.v2 ./deploy/scripts/restore-postgres-temporary.sh \
  backups/postgres/aipickstock-YYYYMMDDTHHMMSSZ.dump \
  aipickstock_restore_YYYYMMDD
```

恢复后脚本输出 Alembic 版本和各表统计，并保留临时库供人工核对。它不会切换应用数据库，也不会自动删除临时库。核对完成后如需删除，必须由运维人员再次确认准确库名并单独执行。

## 保留策略

先预览 14 天以前的备份：

```bash
./deploy/scripts/prune-postgres-backups.sh backups/postgres 14
```

确认输出的每个路径后再执行：

```bash
./deploy/scripts/prune-postgres-backups.sh backups/postgres 14 --apply
```

清理脚本只匹配 `aipickstock-*.dump` 及其校验文件，不处理旧 SQLite 备份或 Docker 数据卷。

# 个人股票与基金持仓工具：一期需求理解

> 状态：终版，用户已于 2026-08-24 确认全部推荐方案
> 分支：`feature/portfolio-watchlist-v2`
> 原则：新产品不沿用旧 Streamlit 产品的信息架构和交互设计；旧代码与 Git 历史保留，不直接覆盖线上版本。

## 1. 一句话目标

建设一个面向个人投资者的简洁 Web 投资账本，让用户通过“持有”和“自选”两个核心入口管理 A 股与国内公募基金，并为后续港股、美股及更多资产类型预留稳定扩展边界。

## 2. 用户与使用场景

- 目标用户：希望集中查看股票、基金持仓和观察标的的个人投资者。
- 使用设备：以桌面浏览器为主要操作端，同时保证手机浏览器可以完成核心操作。
- 使用方式：用户通过邮箱和密码自行注册，登录后只能访问自己的投资账户、持仓和自选数据。
- 产品性质：投资记录与展示工具，不连接券商下单，不提供投资建议或收益承诺。

## 3. 已确认的产品范围

### 3.1 账户体系

- 使用邮箱和密码自行注册。
- 一期不限制为“仅管理员创建账户”。
- 一期不强制邮箱验证。
- 支持注册、登录、退出和会话失效。
- 所有投资账户、持仓、自选分组和自选标的均按用户隔离。

### 3.2 资产范围

- 一期支持 A 股和国内公募基金，默认人民币计价。
- 资产主数据独立保存资产类型、市场、币种和市场代码。
- 后续支持港股、美股等市场时，不修改用户、投资账户和持仓之间的核心关系。
- 同一基金的不同份额类别按不同基金代码管理，不能仅按名称合并。

### 3.3 产品导航

登录后的一级业务菜单只有：

1. 持有
2. 自选

注册、登录、个人设置和退出属于辅助入口，不增加一级业务菜单。搜索标的是添加持仓和自选时的共用能力，不单独占用一级菜单。

### 3.4 持有管理

- 一个用户可创建多个投资账户，例如“证券账户”“支付宝基金”“长期账户”。
- 支持查看全部账户汇总，也支持查看单个投资账户。
- 支持添加、编辑、删除和移动股票或基金持仓。
- 同一股票或基金可以存在于不同投资账户中。
- 股票展示持有数量、持仓成本、最新价格、当前市值、持有收益和收益率。
- 基金展示持有金额、持仓成本、持有份额、最新净值、持有收益和收益率；推算值必须与用户精确录入值明显区分。

### 3.5 基金双录入模式

#### 快速录入

用户填写：

- 当前持有金额
- 持有收益，允许负数
- 数据日期
- 所属投资账户

系统计算：

```text
持仓成本 = 当前持有金额 - 持有收益
持有份额 = 当前持有金额 / 对应官方单位净值
平均成本 = 持仓成本 / 持有份额
```

系统推算的份额和平均成本标记为“系统估算”，同时保存用户的原始输入与录入日期。

#### 精确录入

用户填写：

- 持有份额
- 持仓总成本或平均成本
- 数据日期
- 所属投资账户

系统自动换算持仓总成本与平均成本，并用最新官方净值计算当前市值。

#### 一期边界

- 只管理已经确认的基金持仓。
- 不处理待确认申购和待确认赎回。
- 不要求录入逐笔申购、赎回、定投、分红和手续费。
- 后续增加交易流水时，一期持仓可迁移为一笔期初持仓。

### 3.6 自选管理

- 用户可建立多个自选分组。
- 支持添加 A 股和国内公募基金。
- 支持在分组间移动、删除和查看最新价格或净值。
- 支持将自选标的一键转为持仓，转入时仍需选择投资账户并填写持仓数据。
- 同一标的是否允许重复加入同一分组，需在边界问题中确认。

### 3.7 行情与估值展示

- 股票价格展示来源和更新时间。
- 基金必须区分官方净值与盘中估算净值，不能用同一字段混存。
- QDII 等净值延迟产品按实际净值日期展示，不能伪装成当日净值。
- 行情缺失、请求失败或数据陈旧时明确显示状态，不生成替代数字。
- 金额、份额、价格和收益计算使用十进制定点数，不能使用二进制浮点数直接处理财务结果。

## 4. 一期明确不做

- 社区、资讯流、排行榜、荐股、跟投和达人持仓。
- AI 预测、买卖信号和自动交易。
- 逐笔交易流水、已实现收益和税务批次。
- 截图识别、OCR、CSV 或券商交割单导入。
- 收益日历、周报、月报和历史收益曲线。
- 基金底层持仓穿透、重仓重合分析和组合回测。
- 复杂资产诊断、风险评分和资产配置建议。

## 5. 可验证验收标准

### 5.1 账户与安全

- 新用户可使用未注册邮箱完成注册，并能登录和退出。
- 重复邮箱、非法邮箱和不符合密码规则的请求返回明确错误。
- 未登录用户不能访问持有、自选及其接口。
- 用户甲不能通过修改地址或请求参数读取、修改或删除用户乙的数据。
- 密码仅保存安全哈希，不记录明文；生产会话使用 `Secure`、`HttpOnly` 和 `SameSite` Cookie。

### 5.2 持有

- 用户可以创建至少两个投资账户，并分别添加股票和基金。
- 同一标的可以存在于不同投资账户，全部账户视图汇总正确。
- 股票的数量、成本、市值和收益计算结果可由测试用例复算。
- 基金快速录入按“持有金额－持有收益”计算成本，正收益、零收益和负收益均正确。
- 基金精确录入时，份额、总成本和平均成本可以正确换算。
- 推算份额和用户精确填写的份额在页面上有明确标识。

### 5.3 自选

- 用户可以创建至少两个自选分组。
- 用户可以添加、移动、删除股票和基金，并将自选转为持仓。
- 自选列表展示价格或净值类型、来源及更新时间。

### 5.4 产品边界与扩展性

- 登录后一级业务菜单只有“持有”和“自选”。
- 不支持的市场标的不能被错误识别为 A 股或国内基金。
- 后续增加市场时，无需修改用户、投资账户和持仓的核心关联关系。
- 旧 Streamlit 容器在新产品通过验收前继续可运行，域名切换失败时可以恢复到旧服务。

## 6. 边界与异常场景

- 基金持有收益为负数、零或大于当前持有金额。
- 快速录入日期找不到对应官方净值，无法可靠推算份额。
- 基金官方净值尚未公布，或估算净值与官方净值偏差较大。
- 股票停牌、退市、证券简称或代码发生变化。
- 同一标的重复加入同一个投资账户或自选分组。
- 删除仍有持仓的投资账户，或删除仍有标的的自选分组。
- 用户连续点击保存、浏览器重试或网络超时造成重复请求。
- 行情源更新失败、限流、超时或长期不更新。
- 金额与份额舍入造成单项之和与汇总值出现尾差。
- 未来多币种资产缺少汇率时，不能直接合并为人民币总资产。
- 邮箱未验证时输入错误邮箱，可能影响后续找回密码。
- 开放注册需要防范暴力登录、撞库和批量注册。

## 7. 已确认的边界决策

### 7.1 资产与行情

- 股票范围为沪深北普通股票。
- ETF、LOF 按基金资产管理；一期不支持可转债。
- 国内公募基金包含股票型、混合型、债券型、指数型、货币型、FOF 和 QDII。
- 一期使用免费延时或近实时聚合行情，必须展示来源和更新时间，不承诺交易所实时行情。

### 7.2 持仓、重复与删除

- 股票填写持有股数和持仓总成本，也允许改填平均成本。
- 一期不处理手续费、分红、已实现收益和逐笔交易。
- 基金快速录入找不到对应官方净值时，允许保存金额快照，暂不推算份额。
- 同一投资账户中的同一标的只保留一条持仓；重复添加时由界面进入编辑原持仓，不创建重复记录。
- 同一自选分组中的同一标的不允许重复，但同一标的可以存在于不同分组。
- 非空投资账户和自选分组禁止直接删除，必须先迁移或清空内容。

### 7.3 账户、自选与交付

- 一期提供邮件重置密码，生产部署必须配置 SMTP 邮件服务。
- 自选提供一个可选的关注备注，不提供目标价格。
- 新系统使用全新 PostgreSQL；旧 SQLite 只读备份，不自动迁移。
- 最终验收包含部署并切换 `aipickstock.duckdns.org`。

## 8. 分支与开源工程要求

- 当前只在 `feature/portfolio-watchlist-v2` 开发。
- 功能开发、测试和评审通过后，再经用户明确授权合并到 `dev2.x`。
- `dev2.x` 当前不存在；首次集成时从 `main` 创建，之后 2.x 功能分支从 `dev2.x` 派生。
- `dev2.x` 稳定并完成生产验收后，才通过发布合并进入 `main` 并创建 `v2.x.y` 版本标签。
- `main` 和 `dev2.x` 禁止直接开发、直接推送和强制推送。
- 未经用户明确确认，不执行 `git commit`、`git merge` 或 `git push`。
- 项目按开源工程标准提供 README、贡献指南、行为准则、安全政策、变更日志、Issue/PR 模板、持续集成、依赖锁定和语义化版本。
- 开源许可证属于法律选择，必须由用户确认后才能加入正式 `LICENSE` 文件或公开发布仓库。

# 个人股票与基金持仓工具：交叉验证

> 状态：第二轮交叉验证通过；产品需求已确认，进入设计方案评审。

## 1. 可行性结论

一期需求在技术上可行，但不能建立在现有 Streamlit 页面和 SQLite 表结构上。采用独立 Web 前端、模块化 API 和 PostgreSQL 后，可以覆盖用户隔离、多投资账户、基金双录入、多自选分组以及未来多市场扩展。

## 2. 需求与现状一致项

- 用户已明确要求彻底重新设计，现有约 30 个菜单与“持有、自选”两个入口确实不兼容。
- 现有项目没有用户体系，新增应用级认证是必要变化。
- 现有投资账户为自由文本，新需求需要正式账户实体。
- 现有自选是单一全局集合，新需求需要用户维度和多分组。
- 旧数据源代码已验证“股票价格”和“基金单位净值”必须分路处理，新需求继续保留这一正确口径。
- 当前同步行情会阻塞页面，新系统通过缓存和独立刷新任务隔离后可以改善加载速度。

## 3. 已解决的表面矛盾

### 3.1 彻底放弃旧产品与保留历史

处理方式：新分支建设全新产品，Git 历史和旧生产服务保留；新系统验证成功后再切域名。是否在新分支最终删除旧文件，需要在设计评审后再次确认。

### 3.2 基金快速录入与精确账本字段

处理方式：同时保存用户原始输入、录入模式和计算结果。快速模式在有可靠官方净值时推算份额；精确模式直接保存用户份额。推算值不冒充精确值。

### 3.3 一期仅支持中国市场与未来多市场

处理方式：一期只开放 A 股和国内基金入口，但资产身份从第一天使用市场、代码、币种和交易所字段，不把六位代码当成全球唯一键。

## 4. 第二轮已解决项

### 4.1 邮箱不验证与密码找回

一期允许注册后直接使用，同时提供邮件重置密码。生产环境将 SMTP 作为必需配置；页面明确提示用户核对邮箱。重置接口不泄露邮箱是否存在。

### 4.2 旧数据与新用户归属

旧数据不自动迁移。旧 SQLite 完整备份并只读保留，新用户从全新 PostgreSQL 开始使用，消除归属猜测。

### 4.3 行情“实时”定义

一期接受免费延时或近实时聚合行情，只承诺展示真实来源和更新时间，不承诺交易所实时数据。数据供应方通过适配器隔离，后续可以替换。

### 4.4 资产和操作边界

ETF、LOF 按基金管理，可转债排除；同账户同标的唯一；非空账户和分组禁止删除；净值缺失时保存金额快照；自选只保留可选备注。相关约束可以直接落实为数据库约束、API 错误码和测试。

### 4.5 分支与发布路径

当前 feature 分支开发，首次集成时从 `main` 建立 `dev2.x`，随后通过评审合并；`dev2.x` 稳定后再进入 `main`。该路径比直接覆盖线上版本多一个集成门，符合用户指定流程。
